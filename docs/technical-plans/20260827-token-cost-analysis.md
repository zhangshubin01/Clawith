## 二、钱是谁花的（归因证据链）

1. **v4-pro 全部来自 PenguinHarness agent 会话（"clawith agent 执行任务"本身），不是 Clawith 平台后端。**
   - 平台后端 `agent_runs` 台账：近 24h 共 20 个 run，`model_id` 全部是 deepseek-v4-flash（按小时分组查询，无一 pro）。
   - 平台 Langfuse 可观测性只记录到 flash GENERATION（14 次@06:00 UTC 等），pro 零记录——pro 调用不经过平台的 LLM 埋点路径。
   - 平台 `daily_token_usage`：头部 agent 全天 cache_read 仅 222 万，与账单 pro 的 2.43 亿相差 100 倍。
   - 本机只有两个 DeepSeek 调用方进程形态：PenguinHarness.app（09:44 启动）与 clawith-agent-backend-1。**PenguinHarness 会话时间线与 pro 计费逐小时吻合**：09:59/12:22/12:22/13:18–15:27 四个会话覆盖 09:00–15:00 全部 pro 高峰；其中 13:18 起的会话（e2e_walkthrough.py/mock_llm.py 调试）横跨 14:00–15:00 单小时 320 次请求、¥38.85 的最高峰。
2. **flash ¥6.21 = Clawith 平台后端**（agent run 的 LangGraph 模型步 + compactor 等）。
3. 无 OpenClaw 进程、wwth32 应用 8-20 后无会话，均可排除。

## 三、为什么贵：三个放大机制

### 1. 每次请求平均携带 239K token 的缓存命中前缀
pro 平均每请求：hit 239K + miss 2K + out 1K。前缀 = 系统提示（技能目录/记忆索引/指令） + ~90 个工具 schema + 全量历史 + **每轮 reasoning_content 回放**（DeepSeek 工具调用协议要求完整回传，否则 400）。

### 2. 前缀随会话时长线性膨胀（主因）
逐小时「每请求 hit 输入」实测：

| 小时(+08) | 09 | 10 | 12 | 13 | 14 | 15 |
|---|---|---|---|---|---|---|
| 每请求 hit（千 token） | 152 | 226 | 201 | 213 | **317** | **369** |

从 152K 涨到 369K：长会话把历史、工具输出（含大文件全文）与每轮 reasoning 不断累积进前缀。**14:00–15:00 那一小时 ¥38.85，主要是"长会话跑到第 N 小时"的必然结果，而非任务本身变难。**

### 3. 请求次数高（工具循环）
1016 pro 请求/天；14–15 点单小时 320 次 = 每 11 秒一次。调试型任务（e2e 脚本反复改/跑/读输出）天然产生这种密度。

外部因素：账单里 pro cache-hit 单价 0.15/M 与 0.3/M 并存（12/13 点 0.15，其余 0.3），DeepSeek 计价切换也使 14 点后每 M 输入成本翻倍。

## 四、优化杠杆（按收益排序，均针对 PenguinHarness agent 会话侧）

| 杠杆 | 动作 | 预估省 |
|---|---|---|
| **L1 会话级上下文控制（最大头）** | ①任务拆短会话/按任务边界重开会话（清掉累积历史+reasoning 回放）；②长任务中途主动压缩/裁剪，读大文件用带行号窗口而非整文件回放；③工具输出超过阈值只保留摘要。把平均前缀 239K→100K 即省 ¥36/天 | ~¥36/天 |
| **L2 模型路由** | 机械子任务（grep/文件操作/样板生成/校验）用 v4-flash 子代理（hit 0.1 vs 0.3、out 9 vs 27 每 M，便宜 3×）；v4-pro 只留给设计/疑难调试。一半工作量转 flash 省 ~¥25-30/天 | ~¥25-30/天 |
| **L3 请求数控制** | 动手前先 PLAN（先读代码定位再改，避免"改了跑、跑了错、再改再跑"循环）；复现失败的调试最多 N 轮就换策略。14–15 点 320 次请求若减半省 ~¥19 | ~¥10-19/天 |
| **L4 静态前缀瘦身** | skills 渐进披露（目录只留名字+触发词，SKILL.md 按需 read_file 加载）；MCP 按需挂载（github 40+ 工具、langfuse 30+ 工具不挂就不占前缀） | 每请求固定开销 + 新会话 miss |
| **L5 平台侧（¥6.21，同构问题）** | `max_tool_rounds` 已回到 10000 默认（用户决策），超长循环护栏只剩熔断器；如需收紧可再议。gitlab-mcp 116 工具已删、openviking 已裁——schema 侧历史包袱已清 | 边际 |

L1+L2 落地后预估：¥99/天 → **¥30-40/天** 量级（不损任务质量，机械活全走 flash）。
